#### 🌿 Опис гілок (Branching Strategy)
У проєкті використовуються такі основні гілки:
* **`main`** — основна стабільна гілка. Завжди містить працездатний та перевірений код.
* **`feature/<назва-фічі>`** — тимчасові гілки для розробки окремих функцій або завдань (наприклад, `feature/health-check`).

---

### ✍️ Домовленість про повідомлення комітів (Conventional Commits)
Ми дотримуємося стандарту форматування повідомлень комітів: `тип (область): короткий опис`. Основні типи:
* `feat` — додавання нової функціональності
* `fix` — виправлення помилки
* `docs` — зміни у документації
* `style` — форматування коду, пробіли, відступи (без зміни логіки)
* `refactor` — рефакторинг коду
* `chore` — підтримка проєкту, налаштування (наприклад, початкова структура)

*Приклад коміту:*
```bash
git commit -m "feat (api): додано версію в /health"
```
